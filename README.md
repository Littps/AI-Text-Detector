# AI-Text-Detector

本地多引擎 AI 生成文本检测工具——粘贴即测、下载透明、UI 认真。Windows 桌面应用，模型跑在自己机器上，文本不出电脑。

> 开发中（内核已收口）：引擎加载、模型下载、全文高亮、模型管理均已可用，正在做最后的模型补全与界面打磨。

## 特性

- **多引擎交叉**：中英文微调分类器 + 方法型引擎（GLTR 已可用；Fast-DetectGPT、Binoculars 需大显存与额外权重下载）多路验证，句子取最高分、整篇取长度加权平均
- **本地推理**：全部模型本地运行，无账号、无云端、无按次收费
- **下载透明**：模型勾选制按需下载，Range 断点续传 + SHA256 校验，前端进度 = 后台真实状态
- **结果可读**：六档概率渐变的全文高亮、逐句引擎分数、整篇 AI 率汇总
- **硬件自适应**：NVIDIA 显卡自动选型（CUDA），无卡机器回落 CPU；显存预算内 LRU 调度，重引擎独占运行

## 技术栈

| 层 | 选型 |
|---|---|
| 桌面壳 | Tauri 2.x（Rust + WebView2） |
| 推理后端 | Python 3.14 sidecar（独立进程） |
| 深度学习 | PyTorch 2.9（CUDA / CPU 自适应） |
| 通信 | WebSocket 数据通道 + 进程引导 |

## 快速开始

前置：Windows 10/11 + WebView2、Python 3.14、Node 22、Rust（stable）。

```bash
git clone https://github.com/Littps/AI-Text-Detector.git
cd AI-Text-Detector/v0.2.0-P1
```

依赖安装、开发启动、测试与打包命令见[构建与开发](https://github.com/Littps/AI-Text-Detector/blob/main/docs/BUILD.md)。首次启动会自动探测显卡并给出模型下载建议；也可以先在「模型管理」里按需勾选。

## 为什么会有这个项目？
因为受够了。

如果你曾经被某款“免费本地 <mark>AIGC</mark> 检测工具箱”折磨过，那么你大概率经历了和我一样的事情：

**第一，它连最基本的网络环境都处理不好。**
它硬编码了国内镜像源，导致你开代理时 pip 报错，关代理时连不上 HuggingFace。哪怕你是个能在浏览器里丝滑访问外网的正常用户，它也会在进度条 5% 的时候给你弹一个红色的 `ValueError`。更好笑的是，它的后台进程极其粗暴地挂载在 `python.exe` 下——你打开任务管理器，根本分不清哪个是你自己跑的项目，哪个是它驻留的毒瘤。

**第二，它的核心算法甚至存在逻辑错误。**
有热心的大佬提交过包含 **14 个严重缺陷修复** 的 PR，里面包括“Binoculars 模块分子分母用错导致伪判”、“模型加载后显存不释放导致 OOM”、“中文长文未截断导致崩溃”。结果呢？原作者不仅没去合并这个硬核修复，反而去接入了所谓 19GB 的 Humanizer 模型，`yinb3` 提交的修复 PR 至今处于 `Conflicts` 状态。一个连别人帮忙修 Bug 都看不懂、理不顺的项目。

**第三，它又当又立。**
UI 丑得像是用 10 年前的 Web 框架强行糊出来的，图标像是 AI 花了一秒钟随机生成的。左下角明晃晃写着“免费版（预留收费接口）”，甚至在后来的版本里还试图加入**打款码和 Telegram 引流**。而它的 README 顶部，却挂着 **PolyForm Noncommercial 协议禁止商用**。

**第四，你无法得到任何技术支持。**
去它的 Issues 区看看，全是被网络问题卡住、被报错弹窗折磨的用户。他们没有得到支持，甚至是一句回复。而那个提交 PR 试图拯救这个项目的 `yinb3`，我想最终也心死了。

### 所以我自己写了一个。

- 我只做了三件事：下载、检测、展示结果。
- 下载进度是真实的，前后端是严格同步的。
- 网络请求是自动适配的，不强迫你绑定任何镜像源。
- 进程是可以干净杀死的，不留任何后台幽灵。
- 核心逻辑是清晰的，没有那个“PR 问题辈出”的烂摊子。
- 会认真对待使用体验与技术问题。

本项目采用 **MIT 协议**。我只想它真的能用。
